# 本地 AI 知识库系统 - 简历项目描述

## 项目概述

基于 RAG（检索增强生成）架构的私有文档智能问答系统，支持 PDF/Word/Markdown/TXT 等多格式文档入库，通过向量检索 + BM25 关键词检索 + RRF 融合 + Cross-Encoder 重排序实现高精度召回，配合多 Agent 编排实现意图路由、知识库问答、网络搜索、文档概览等场景。

## 技术栈

- **后端框架**：Spring Boot 4.0.6 + Spring AI 2.0.0-M4 + Java 21
- **向量数据库**：Elasticsearch 9.x（主力，IK 分词）+ PostgreSQL + PgVector（降级）
- **消息队列**：Redisson（文档解析异步队列）
- **缓存**：Caffeine（本地缓存）+ Redis（会话历史）
- **认证授权**：Spring Security + JWT
- **可观测性**：Actuator + Prometheus + Micrometer
- **LLM 集成**：智谱 GLM-4-Flash / DeepSeek-V4-Flash（OpenAI 兼容协议）
- **Embedding**：智谱 Embedding-3（1024 维）
- **Rerank**：智谱 Rerank API（Cross-Encoder）

## 核心职责与成果

### 1. 双向量存储架构设计

- 设计 ES（@Primary，IK 分词）+ PgVector 双存储方案，ES 故障时自动降级到 PgVector，保证系统可用性
- 预创建 ES 索引时集成 IK 分词器（写入 ik_max_word，查询 ik_smart），提升中文检索召回率
- 实现文档删除/重新解析时同步清理两处数据，保证数据一致性

### 2. 混合检索与重排序优化

- 实现向量召回 + BM25 关键词召回 + RRF（Reciprocal Rank Fusion）融合算法，兼顾语义相近与精确词命中
- 使用堆排序优化 RRF 融合复杂度至 O(n log k)，相比全量排序 O(n log n) 性能提升显著
- 集成 Cross-Encoder Rerank 精排，对 RRF 候选文档进行细粒度打分，过滤弱相关文档（score < 0.7），提升 Precision@K
- 实现检索层熔断器，连续失败 5 次自动熔断 30s，避免 ES 抖动拖垮整体服务

### 3. Query Rewrite 多轮对话优化

- 设计基于 LLM 的查询改写服务，将用户追问中的指代词（"它""这个"）替换为具体实体，补全省略主语
- 实现历史窗口限制（最近 6 条），避免 token 浪费；设置 1200ms 超时降级，不拖慢首 token 延迟
- 配合追问检测器（关键词规则）+ 上文注入，进一步提升多轮对话召回质量

### 4. 多 Agent 编排与意图路由

- 设计多 Agent 编排框架，实现意图路由（LLM 分类）+ 6 大 Agent（知识库/搜索/文档概览/热点/规划/聊天）
- 实现 SSE 流式输出，首字延迟 <3s，完整答案实时流式返回
- 集成 ThinkBlockStripper 过滤 LLM 思考块，减少 token 消耗；实现错误分类与降级渲染，提升用户体验

### 5. 文档入库自适应限速

- 设计类似 TCP 拥塞控制的自适应限速策略：遇到 429 限流时暂停递增 2s 并指数退避重试，成功后暂停递减 500ms
- 实现分批入库（每批 50 chunks）+ 进度回调（每 500 条更新 DB），避免大文件解析阻塞用户
- 实现文本编码自动检测（UTF-8 → GB18030 → 系统默认），解决中文 txt 乱码问题

### 6. 多层缓存与性能优化

- 设计 Embedding 缓存装饰器，缓存单条 embedding 调用（maxSize=2000，TTL=10min），命中率约 40%
- 实现检索结果缓存（Key: userId|topK|rerankSig|query），TTL 10min，文档入库/删除时主动失效
- 配置专用检索线程池（core=CPU*2，max=32），避免阻塞 IO 占满 ForkJoinPool.commonPool()

### 7. 安全与权限控制

- 实现 JWT 认证 + Spring Security 授权，支持 ADMIN / USER 角色
- 设计文档权限模型（doc_scope: PUBLIC / PRIVATE），实现用户隔离检索（PUBLIC OR (PRIVATE AND user_id == userId)）
- 实现多维度限流（匿名用户 20 次/小时，已认证用户 QPS=2，每日上限 200，IP QPS=5）

### 8. 可观测性建设

- 集成 Actuator + Prometheus + Micrometer，暴露 /actuator/prometheus 端点供 Grafana 抓取
- 自定义业务指标：Embedding 缓存命中率、检索熔断器状态、Chat 错误计数（按错误码拆分）、Chat 耗时（按模型拆分）
- 实现用户自备 ChatModel 配置（API Key AES 加密入库），支持运行时模型切换

## 技术难点与解决方案

| 难点 | 解决方案 |
|------|----------|
| ES 429 限流导致入库失败 | 自适应限速（类似 TCP 拥塞控制）+ 指数退避重试 |
| 中文 txt 编码检测不可靠 | 绕过 Tika，手动检测 UTF-8 → GB18030 → 系统默认 |
| 向量 score 与 BM25 score 量纲不同，无法加权融合 | 采用 RRF（Reciprocal Rank Fusion）基于排名融合，不依赖 score 量纲 |
| 多轮对话指代词导致召回质量下降 | Query Rewrite（LLM 改写）+ 追问检测 + 上文注入 |
| ES 检索抖动拖垮整体服务 | 检索层熔断器，连续失败自动熔断 30s |
| Embedding 单次调用耗时 ~2.7s | Embedding 缓存装饰器 + 检索结果缓存 |
| 大文件解析阻塞用户 | Redisson 异步队列 + 进度回调 |

## 项目亮点

1. **双向量存储架构**：ES + PgVector 双存储，ES 故障时自动降级，保证高可用
2. **混合检索 + 重排序**：向量 + BM25 + RRF + Rerank 四层召回，兼顾语义与精确匹配
3. **自适应限速**：类似 TCP 拥塞控制，自动收敛到最优吞吐速率，无需人工调参
4. **多 Agent 编排**：意图路由 + 6 大 Agent，支持知识库问答/网络搜索/文档概览等场景
5. **多层缓存**：Embedding 缓存 + 检索结果缓存 + SystemPrompt 缓存，显著降低延迟
6. **熔断降级**：检索层熔断器，连续失败自动熔断，避免单点故障拖垮整体服务
7. **可观测性**：Actuator + Prometheus + 自定义指标，全面监控业务健康度
8. **安全与权限**：JWT 认证 + 文档权限模型 + 多维度限流，保证系统安全

## 数据指标（示例）

- **文档入库**：单库 10w+ 文档块，50MB 文档入库耗时 ~5min
- **检索性能**：混合检索平均耗时 ~500ms，缓存命中时 ~50ms
- **缓存命中率**：Embedding 缓存命中率 ~40%，检索结果缓存命中率 ~30%
- **首字延迟**：SSE 流式首字延迟 <3s
- **错误率**：Chat 错误率 <1%（超时/网络异常/LLM 重试耗尽）

## 未来优化方向

- **评测体系**：构造评测集，跑 Recall@K / MRR / nDCG，量化检索效果
- **语义分块**：基于语义相似度的动态分块，提升检索召回率
- **HyDE**：用 LLM 生成"假设性答案"再 embedding 检索，提升长尾问题召回
- **语义缓存**：基于 embedding 相似度的历史答案复用，进一步降本
- **Token 计量**：按用户/模型统计 token 消耗，估算成本
