# 知识库问答系统（local-ai-knowledge）详细技术文档

> 基于 Spring Boot + Spring AI 的企业级 RAG 知识库问答系统。

---

## 1. 系统架构总览

```
用户请求 → Controller → MultiAgentOrchestrator → Agent → 检索/LLM → SSE 流式响应
                     → DocumentParseService → Tika解析 → 切片 → ES+PG 入库
```

**技术栈**：Spring Boot, Spring AI, Elasticsearch, PostgreSQL, Redis/Redisson, Apache Tika, Reactor/SSE, Caffeine

---

## 2. 数据模型

name（唯一标识）、content（含 {context} 占位符）、isDefault

## 4. 多Agent调度体系

### 4.1 架构概览
```
用户问题 → IntentRouter（意图路由）
  ├→ KNOWLEDGE    → KnowledgeAgent    （知识库检索问答）
  ├→ CHAT         → ChatAgent         （通用闲聊）
  ├→ PLANNER      → PlannerAgent      （ReAct多步规划）
  ├→ HOT_SEARCH   → HotSearchAgent    （热榜查询）
  ├→ DOC_OVERVIEW → DocumentOverviewAgent（知识库概览）
  └→ DOC_SEARCH   → DocumentSearchAgent （文档内搜索）
```

### 4.2 AgentType 枚举
| 值 | sourceTag | 用途 |
|----|-----------|------|
| KNOWLEDGE | knowledge_base | 检索私域文档 |
| CHAT | llm_direct | LLM直答 |
| PLANNER | planner | 多步推理 |
| HOT_SEARCH | hot_search | 热榜数据 |
| DOCUMENT_OVERVIEW | knowledge_base | 总结所有文档 |
| DOCUMENT_SEARCH | knowledge_base | 全文检索定位 |

### 4.3 SpecializedAgent 接口
每个Agent实现三个方法：`type()`（类型）、`systemPrompt()`（提示词）、`execute(request)`（流式执行）。通用逻辑由Orchestrator统一处理。

### 4.4 RagToolContext — 工具调用上下文（请求级）

**两大职责**：
1. 隐式传递 userId（防prompt注入篡改）
2. 回收调用记录（工具名、检索文档），供构建META

关键字段：userId、modelKey、rewrittenQuery、invokedTools（Set）、retrievedDocs（List）

**Step事件流**：通过 Reactor Sinks.Many 推送可视化事件，格式 `[STEP]{json}[/STEP]`，stage包括 route/rewrite/tool/think/act/observe/generate/done

### 4.5 MultiAgentOrchestrator — 调度中枢（最核心类）

#### chatStream() 完整流程：

**Step 1 模式判断**：normalizeMode → "LLM"或"KNOWLEDGE"，forceLlm时跳过路由

**Step 2 意图路由**：forceLlm→CHAT，否则IntentRouter.route(question)

**Step 3 构建system prompt**：Agent内置 + 用户自定义合并；thinking=false时前缀加"/no_think\n"

**Step 4 构建消息列表**：ChatMessageBuilder.build() → SystemMessage + 历史（同模式过滤）+ UserMessage + token裁剪

**Step 5 保存用户消息**：ChatHistoryCacheService双写Redis+DB

**Step 6 上下文增强**：
- 推送route事件
- 追问检测：FollowUpDetector.isFollowUp() → 命中则加载上一条assistant回答
- Query Rewrite：仅KNOWLEDGE模式+有历史时，调用QueryRewriteService改写

**Step 7 执行Agent**：
- 追问上下文注入（倒数第二位插入SystemMessage）
- agent.execute(request) → token流
- ThinkBlockStripper 实时过滤 `<think>` 块
- 超时：首字节15s，空闲25s
- Flux.merge(step事件流, token流)

**Step 8 后处理**：
- 正常→附加[META]块
- 异常→StreamErrorHandler分类+兜底文案
- doFinally→cleanAnswer()清洗 + 持久化assistant消息

#### cleanAnswer() — 回答清洗
依次用正则去除：`<think>`块、`[STEP]`块、元描述行、内联来源标签、参考来源页脚、工具调用前导语、多余换行

#### ThinkBlockStripper — 流式`<think>`块剥离

**难点**：流式token逐个到达，标签可能跨chunk（如`<thi` + `nk>`）。

原理：维护buffer+inThink状态，查找开始/结束标签；`trailingSafeLen()`计算buffer末尾可能是标签前缀的部分，暂不输出等下个chunk确认。

### 4.6 IntentRouter — 意图路由器

**两级决策**：
1. **快速匹配**（<1ms，覆盖~80%）：关键词集合匹配（热榜/规划/搜索/概览/元问题/打招呼）
2. **LLM分类**（~200ms）：发一次短调用让LLM输出标签，超时2s→fallback KNOWLEDGE

**设计原则**：宁可多查一次知识库也不遗漏（默认fallback KNOWLEDGE）

### 4.7 KnowledgeAgent — 知识库专家（最核心Agent）

execute()流程：
1. **主动检索**：用rewrite query调searchKnowledgeBase()
2. **去元词重试**：首次为空→去掉"帮我/总结/知识库"等干扰词重试
3. **宽泛检索**：二次为空→用通用词"文档 内容 介绍 概述"
4. **注入结果**：在UserMessage前插入`【知识库检索结果】`
5. **流式调LLM**

System Prompt核心规则：严格归因（禁止脑补）、无来源标注（UI单独展示）、安全准则

### 4.8 ChatAgent — 通用对话
最简单，无工具，直接 chatClient.prompt().messages().stream().content()

### 4.9 PlannerAgent — ReAct规划器（最复杂Agent）

**Think→Act→Observe循环**（最多4轮）：
1. Think：同步调LLM输出JSON `{"thought","action","query","answer"}`
2. action判断：finish→streamFinalize / search_kb / web_search / get_hot_list
3. 工具结果作为UserMessage追加，回到Think
4. 工具调用累计不超3次

**streamFinalize**：替换prompt禁止JSON，用subscribe桥接到外部FluxSink实现真流式；失败兜底用PlanStep.answer按40字切片输出

### 4.10 HotSearchAgent — 热榜专家
主动查HotSearchService→有数据注入上下文→无数据降级为通用推荐prompt

### 4.11 DocumentOverviewAgent — 文档概览
Caffeine缓存(60s)→获取用户所有已完成文档(最多10份)→逐文档用文件名检索3个代表片段→拼接概览上下文

### 4.12 DocumentSearchAgent — 文档内搜索
提取搜索词（引号内>搜索模式>去前缀）→BM25关键词检索→按文档分组展示

### 4.13 KnowledgeTools — 知识库工具
@Tool方法，从ToolContext取RagToolContext→记录调用→混合检索→emitStep→格式化返回

### 4.14 ChatMessageBuilder — 消息构建器
SystemMessage + 历史(同模式过滤, 最多20条) + UserMessage + token裁剪。resolveAgentSystemPrompt: Agent内置prompt + 用户自定义prompt合并

### 4.15 MetaBuilder — META构建器
构造`[META]{json}[/META]`：source判定（knowledge_base/llm_direct/hot_search/planner）、agent、invokedTools、hitCount、queryRewrite、references（按source去重的引用卡片）、disclaimer、error

### 4.16 StreamErrorHandler — 错误处理
| 错误码 | 触发 | 文案 |
|--------|------|------|
| timeout_first_byte | 首字节15s超时 | AI服务响应超时 |
| timeout_idle | 中间25s无内容 | 流式中断 |
| rate_limit | 429 | 请求过于频繁 |
| auth | 401/403 | 认证失败 |
| content_policy | 内容安全 | 触发安全策略 |

### 4.17 FollowUpDetector — 追问检测
规则：问题≤30字 + 命中追问关键词（序数引用/历史指代/追问动作/文档指代/总结类）→加载最近同模式assistant消息(截取2000字)注入上下文。isSameMode：从metadata.chatMode判断模式隔离。

### 4.18 ChatModelRegistry — 多模型注册表
启动时注册@Primary为default + 按配置构建其他OpenAiChatModel。getClient(modelKey)返回对应ChatClient，未知key走default。

## 5. 核心服务层

### 5.1 ChatHistoryCacheService — 聊天历史（Redis热缓存+DB持久化）
- **saveMessage**：先DB后Redis，Redis失败→删key保一致性
- **loadRecentHistory**：Redis→miss→DB→回填Redis，TTL 4小时+读时续期
- **deleteSession**：Redis+DB双删

### 5.2 QueryRewriteService — 查询改写
解决多轮对话代词指代问题（"它的最新版本"→"Spring AI的最新版本"）。历史<2条或问题≤3字不改写，调LLM改写(超时3s)→返回RewriteResult(attempted,changed,query,costMs,reason)

### 5.3 RerankService — 交叉编码器重排序
对混合检索初筛结果POST到SiliconFlow Rerank API，按relevance_score降序+阈值过滤+取topN，将rerank_score写入metadata。失败→返回原始列表。

### 5.4 EmbeddingService — 向量化
embed(单文本)、embedBatch(批量)、embedBatchWithChunking(分批+批间200ms防限流)、cosineSimilarity

### 5.5 SystemPromptService — Prompt管理
Caffeine缓存10分钟。读走缓存(@Cacheable)，写清缓存(@CacheEvict allEntries)

### 5.6 WebSearchService — 网络搜索（Tavily API）
知识库无结果时降级调用。用JDK HttpClient避免Reactor线程block问题。

### 5.7 HotSearchService — 热搜查询
从crawler_hot_item表查各平台热榜（B站/微博/知乎/GitHub/抖音/小红书），今日无数据查昨日，按title去重，跨平台截断20条。

## 6. 文档解析与入库

### DocumentParseService 流水线

**registerAndSubmit**：生成UUID→保存文件→创建DB记录→提交Redisson队列

**parseAndImport**（消费者调用）：
1. 状态→PARSING
2. .txt直接读取 / 其他Tika解析
3. TextCleanUtil.clean() 清洗
4. TextSplitterUtil.splitText() 切片（800字/片，100字重叠）
5. 状态→IMPORTING
6. ES导入（EsVectorStoreService.importChunksWithAdaptiveRate）
7. PG导入（原文存储）
8. 状态→DONE

**deleteDocument**：删ES向量+PG分片+本地文件+清检索缓存

### EsVectorStoreService — 自适应限速导入

每批50条，遇429指数退避(3s×2^retry)，全局自适应暂停(成功减500ms/失败加2000ms/上限8000ms)

### DocParseQueueConsumer — 队列消费者
应用启动后2个线程循环poll Redisson队列(超时5s)，取到taskId调parseAndImport。优雅关闭(@PreDestroy)。

## 7. 混合检索引擎

### HybridSearchService 核心流程
1. **缓存检查**（Caffeine）
2. **熔断器保护**（SimpleCircuitBreaker）
3. **并行双路召回**：ES向量检索 + ES BM25关键词检索
4. **RRF融合排序**：`score(d) = 1/(60+rank_vector) + 1/(60+rank_bm25)`，两路都靠前的文档分数最高
5. **Rerank重排序**（可选）：Cross-Encoder精排
6. **取TopK + 缓存**

### EsVectorSearchService — 向量检索
Spring AI VectorStore接口，用户隔离：(PUBLIC) OR (PRIVATE AND user_id=X)

### EsKeywordSearchService — BM25关键词检索
ES Java API Client，match_phrase保持短语完整性，同样的ownership过滤

## 8. 工具类

### ChatContextUtil — Token管理
安全阈值19660(~60%×32K)，trimByToken：从最早user+assistant成对删除，增量O(n)计算

### TextSplitterUtil — 文本切片
一级断句(句号/问号等)→二级断句(顿号/冒号)→动态合并(≤800字)→重叠区(100字回溯)→超长兜底(700字步进)

### TextCleanUtil — 文本清洗
去制表符、全角空格、多余空格/换行、首尾trim

### RagFormatUtil — 检索结果格式化
`【1】[来源: 文件.pdf]\n内容...\n\n`

### SimpleCircuitBreaker — 轻量熔断器
CLOSED→(失败≥N)→OPEN→(冷却)→HALF_OPEN→(探测成功)→CLOSED。AtomicReference+CAS线程安全。

## 9. 全链路流程图

### 问答流程
```
用户提问 → RagController.chatStream()
  → MultiAgentOrchestrator.chatStream()
    → 模式判断(KNOWLEDGE/LLM)
    → IntentRouter.route() 意图路由
    → ChatMessageBuilder.build() 构建消息
    → FollowUpDetector 追问检测
    → QueryRewriteService 查询改写
    → Agent.execute() 执行
      → KnowledgeAgent: 混合检索→注入结果→LLM流式
      → PlannerAgent: Think→Act→Observe循环→流式finalize
      → ChatAgent: 直接LLM流式
    → ThinkBlockStripper 过滤think块
    → MetaBuilder 构建META
    → cleanAnswer 清洗→持久化
  ← SSE流(token + [STEP] + [META])
```

### 文档入库流程
```
上传文件 → DocumentController.upload()
  → DocumentParseService.registerAndSubmit()
    → 保存文件 → 创建DB记录 → 提交Redisson队列
  ← taskId

DocParseQueueConsumer.consumeLoop()
  → DocumentParseService.parseAndImport()
    → Tika解析 → 文本清洗 → 切片(800字+100字重叠)
    → ES导入(自适应限速) + PG导入
  ← 状态更新为DONE
```

### 检索流程
```
query → HybridSearchService.searchWithOwnership()
  → 缓存检查 → 熔断器保护
  → 并行: ES向量检索 + BM25关键词检索
  → RRF融合排序
  → Rerank重排序(可选)
  → TopK + 缓存
← Document列表
```
