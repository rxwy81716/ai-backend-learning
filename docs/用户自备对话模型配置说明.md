# 用户自备对话模型（Chat）配置说明

本文说明 **local-ai-knowledge** 与 **local-ai-knowledge-front** 中与「用户自定义 OpenAI 兼容 Chat（baseUrl / API Key / model 等）」相关的实现：数据表、接口、运行时解析、缓存与 Redis 广播、前端入口。  
**Embedding 与向量维度** 仍为全局默认配置，不在本文范围内。

---

## 1. 功能概览

| 能力 | 说明 |
|------|------|
| 配置存储 | PostgreSQL 表 `user_chat_model_config`，API Key 以 **AES-256-GCM** 密文存储。 |
| 命名约定 | 前端 / SSE 请求体字段 `model` 使用 **`user:{alias}`**，与系统内置 `glm`、`deepseek`、`default` 等区分。 |
| 运行时解析 | `ChatClientResolver`：先判是否 `user:` 前缀；是则按当前登录用户 + alias 读库构建 `ChatClient`；否则走 `ChatModelRegistry`。 |
| 对话链路 | `KnowledgeAgent`、`ChatAgent`、`PlannerAgent` 均通过 `ChatClientResolver.resolve(userId, modelKey)` 取客户端，保证与 SSE 所选模型一致。 |
| 多实例缓存 | `ChatClient` **不放入 Redis**（不可序列化）；各节点 **内存缓存** + Redis **Topic 广播失效**（`UserChatModelEvictPublisher` / `UserChatModelEvictSubscriber`）。 |

---

## 2. 数据库

- 脚本路径：`local-ai-knowledge/src/main/resources/db/user_chat_model.sql`
- 首次部署请在目标库执行该脚本。
- 约束：`UNIQUE(user_id, alias)`；`alias` 业务校验见 `UserChatModelService`（禁止与 `default` 冲突等）。

---

## 3. 后端配置（application.yml）

- 配置节：`app.user-chat-model.encryption-secret`
- **留空**：由 `app.jwt.secret` 与固定盐派生 AES 密钥（便于本地开发）。
- **生产建议**：设置环境变量 `USER_CHAT_MODEL_ENC_SECRET`（或 YAML 中显式长密钥），避免改 JWT 后无法解密历史密文。

---

## 4. HTTP 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/user/chat-models` | 当前用户配置列表（需登录）；返回 VO，含脱敏 `apiKeyHint`。 |
| POST | `/api/user/chat-models` | 新建或更新；更新时 `apiKey` 可空表示不改密文。 |
| DELETE | `/api/user/chat-models/{id}` | 删除；校验归属 `user_id`。 |
| POST | `/api/user/chat-models/try` | 明文参数连通性测试，不落库。 |
| POST | `/api/user/chat-models/{id}/try` | 对已保存记录解密后测试。 |
| GET | `/api/rag/models` | 未登录仅系统 keys；已登录合并 `user:{alias}`，供前端下拉。 |

安全：`/api/user/**` 在 `SecurityConfig` 中需认证；控制器内再次 `SecurityUtil.getCurrentUserId()` 校验。

## 5. 核心类与职责（Java）

| 类 | 职责摘要 |
|----|----------|
| `UserChatModelController` | REST 入口，见上表。 |
| `UserChatModelService` | 校验、加解密、CRUD、探测调用；写库后 `evictLocalAndBroadcast`。 |
| `UserApiKeyCrypto` | AES-GCM 加解密。 |
| `UserChatModelConfigMapper` / `UserChatModelConfig` | MyBatis 与实体。 |
| `UserChatModelKeys` | `user:` 前缀与 alias 解析工具。 |
| `OpenAiCompatibleChatModelFactory` | 与 YAML 注册表共用的 OpenAI 兼容 `ChatModel`/`ChatClient` 构建。 |
| `ChatModelRegistry` | 仅负责 **YAML** 多模型；用户 `user:` 模型不在此注册。 |
| `ChatClientResolver` | 统一解析 `model`；用户模型 **进程内 ConcurrentHashMap 缓存**。 |
| `UserChatModelEvictPublisher` | 向 Redis Topic `local-ai:user-chat-model-evict` 发布 `userId:alias`。 |
| `UserChatModelEvictSubscriber` | 启动订阅 Topic，收到后对本机 `ChatClientResolver` 执行 `evict`。 |
| `RagController` | `listModels` 合并用户 keys；`chat/stream` 将 `body.model` 传入编排器。 |

DTO：`UserChatModelSaveDto`、`UserChatModelTryDto`、`UserChatModelVo`（见包 `model.dto`）。

---

## 6. 为何缓存不用 Redis 存 ChatClient

- Spring AI 的 `ChatClient` / 底层 HTTP 客户端 **无法安全序列化** 到 Redis，也不应在多实例间共享连接对象。
- 合理做法：**实例本地缓存** 已构建的 `ChatClient`；配置变更时 **本地 evict** + **Redis Pub/Sub 通知其他节点 evict**。
- 若仅需单机，Redis 广播失败不影响功能（Publisher 已捕获异常打日志）。

## 8. 使用步骤（给最终用户）

1. 在数据库执行 `user_chat_model.sql`（若尚未执行）。
2. 登录系统，打开 **对话模型配置**，新增一条：填写 baseUrl、API Key、模型名等；可用「测试连接」验证。
3. 打开 **智能问答**，在「对话模型」下拉里选择 **`user:你的别名`**（或继续选系统默认）。
4. 发起对话后，请求体会携带 `model`，后端按本文逻辑解析。
